# 组织架构

## 1. 功能目标

基于 `sys_user` 维护金字塔式组织架构，提供新增下级、调整上级、查看上下级关系和模块授权入口，并为数据权限提供 `tree_path` 基础。

## 2. 功能范围

- 查询整棵组织树
- 查询直属下级
- 查询上级链
- 新增下级用户
- 调整上级
- 更新节点
- 删除节点
- 启停节点
- 配置用户可访问模块

## 9. 权限规则

- 路由为 `adminOnly`
- 组织树查询与数据范围依赖 `tree_path`
- 超级管理员拥有更高可见范围
- 模块授权保存后，左侧菜单和路由访问会按最新授权变化

## 13. 页面操作步骤
### 第一步：
进入 `/org-tree`，在组织树中选择当前要查看或维护的节点。
### 第二步：
在详情区查看当前节点的直属下级、上级链、单位信息和组织树字段。
### 第三步：
如需调整结构，可执行新增下级、编辑节点、调整上级、启停或删除操作。
### 第四步：
如需控制菜单访问范围，可打开当前节点对应用户的“可访问模块配置”，保存后回看权限效果。

## 14. 常见问题

- 组织架构与用户管理容易职责混淆
- 节点移动目标若是自己或下级，会触发前端/后端双重拦截
- 单位调整会影响整棵子树，不是只影响当前节点

## 15. 风险点

- `tree_path` 一旦错误，会影响组织查询、数据权限、审批链等多个模块
- 节点移动和单位同步属于高联动操作
- 模块授权与菜单显示存在明显联动，保存后效果会立即体现

## 16. 防回归点

- 验证移动节点时防循环和路径级联更新正确
