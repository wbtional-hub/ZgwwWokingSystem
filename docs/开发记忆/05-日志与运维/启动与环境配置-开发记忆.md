## 13. 页面操作步骤
### 第一步：
先按 `README.md` 检查 Java、Maven、Node、PostgreSQL 依赖版本，并确认数据库已启动。
### 第二步：
核对 `backend/src/main/resources/application.yml` 与 `frontend/.env.example` 中的环境变量位置和默认值。
### 第三步：
后端优先使用 `mvn -Dspring-boot.run.profiles=wsl spring-boot:run` 或 `start.txt` 中的带 `DB_HOST` 启动方式，前端使用 `npm run dev`。
### 第四步：
使用登录、考勤、AI 会话等真实接口做最小联调；若端口占用或数据源不一致，再回到 `start.txt` 和日志中台排查。

## 14. 常见问题

- 本地看似启动成功，但实际连到了错误数据源
- 8080 被占用时，后端并非业务故障，而是环境端口冲突
- 前端代理未对准后端端口时，登录 403、接口 404 容易被误判为业务问题
- AMap Key 未配置时，单位打卡点和考勤定位能力会退化

## 15. 风险点

- Windows、WSL、服务器三套环境容易出现端口、路径、数据源差异
- 旧的 `start.txt` 命令若长期不回看，容易与现有实际启动口径偏离
- 启动异常常常会伪装成 AI、登录、考勤等业务问题

## 16. 防回归点

- 验证 PostgreSQL 可连通、数据库名正确
- 验证后端启动日志中的端口和数据源正确
- 验证前端代理目标与后端端口一致
- 验证登录、考勤、AI 三条最小业务链至少各成功一条
