# 操作日志

## 1. 功能目标

- 记录系统关键操作并提供审计查询入口。
- 为“谁在什么时间做了什么变更”提供最小可追溯能力。

## 2. 功能范围

- 操作日志列表查询。
- 按模块、操作人、时间范围查询。
- 查看模块、动作、业务 ID、内容与时间。

## 3. 菜单位置

- 一级菜单：操作日志
- 模块编码：`OPERATION_LOG`

## 13. 页面操作步骤
### 第一步：
进入 `/operation-logs`，先选择模块、操作人和时间范围。
### 第二步：
执行查询，并先查看“当前查询工作面”摘要，确认当前筛选口径。
### 第三步：
在日志列表中核对模块、动作、业务 ID、操作内容和时间。
### 第四步：
如果结果为空，先通过空态入口清空筛选，再重新回到默认日志列表。

## 14. 常见问题

- 操作日志为空不一定是系统没记录，也可能是当前查询条件过窄。
- 操作日志记录的是业务操作，不替代异常日志明细；异常排查仍要配合日志中台。
- 模块名和动作名是固定枚举口径，误改会影响审计可读性。

## 15. 风险点

- `module_name`、`action_name`、`biz_id` 和 `content` 是最小审计主干字段，缺一都会降低追溯价值。
- 若页面不展示“当前查询工作面”，空结果容易被误判为“系统没有日志”。
- 组织树路径过滤失效时，会导致查询范围越界。

## 16. 防回归点

- 验证模块、操作人、时间范围三类筛选可用。
- 验证空态会展示当前查询工作面并支持一键清空。
- 验证登录、删除、导出、权限拒绝等关键交付动作有基础追溯记录。
- 验证组织范围过滤不会越界。
