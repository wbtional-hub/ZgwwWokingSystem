## 13. 页面操作步骤
### 第一步：
先以 `database/00_init_delivery.sql` 作为基线入口，确认基础 schema 和 seed 已执行。
### 第二步：
根据目标功能核对对应专题 SQL 是否已经执行，例如 AI、登录安全、考勤补卡。
### 第三步：
对照关键业务表和参数初始化，确认相关页面所依赖的数据结构真实存在。
### 第四步：
联调失败时优先回看本文件、启动与环境配置文件以及目标模块 mapper，判断是否属于“库未同步”问题。

## 14. 常见问题

- 代码已更新但运行库漏执行 SQL，页面会表现为“看起来能点，实际报错”
- 参数表初始化缺失时，功能可能不是直接报错，而是口径不对
- AI 月报、扫码登录、补卡审批这类新增链路最容易被漏执行专题 SQL

## 15. 风险点

- 基线和专题 SQL 同时存在，人工执行时容易漏掉增量脚本
- AI、登录安全、考勤补卡都属于近阶段新增能力，环境差异风险高
- 数据库问题经常被误判为接口、前端或权限问题

## 16. 防回归点

- 验证目标环境已执行 `00_init_delivery.sql` 对应基线
- 验证新增功能上线前已核对对应专题 SQL
- 验证参数初始化完整，尤其是默认密码、打卡半径、当前工作知识库、微信参数
- 验证关键表实际存在并与 mapper 字段一致
